## 要点（設計に効くもの）

- **AF と手動レンズ位置の指定には Arducam 版 libcamera が必須**（公式）。Raspberry Pi 版の tuning ファイル `imx519.json` には `rpi.af` が無い。そのため、レンズ位置を指定しても "Could not set LENS_POSITION - no AF algorithm" となり設定されない
- **Pi 4 ではセンサー HDR を使えない**。HDR は露出ブラケットを撮ってソフト側で合成する
- RAW は **10bit のみ**。フル解像度 4656×3496 は 9fps
- 最長露光は公称 **200 秒**

## オートフォーカス

- **方式**: PDAF と CDAF（公式）。Arducam 版の `cam_helper_imx519.cpp` が PDAF を解析するのは `target_ == "vc4"` のときだけ。つまり **Pi 4 では PDAF が効く**。Pi 5 では CDAF だけになる（推定）
- **VCM**: AK7375（`ak7375@c`）。overlay の引数 `vcm=off` で無効にできる
- **LensPosition の単位**: Raspberry Pi の文書では「通常はディオプター（1/距離[m]）、0.0 が無限遠」。同じ文書に "Lens calibration is imperfect, so different camera modules of the same model might vary." とある
- **Arducam 版 `imx519.json` の `rpi.af`**
  - normal: min 0.0 / max 12.0 / default 1.0
  - macro: min 3.0 / max 15.0 / default 4.0
  - `"map": [0.0, 0.0, 15.0, 4095]`。0〜15 を VCM コード 0〜4095 に直線で割り当てているだけなので、値が実際のディオプターと一致する保証はない（推定）
- **再現性・ヒステリシス**: 記載なし（未確認）。フォーカススタッキングの前に実測で較正する

## Raspberry Pi 4 でのセットアップ

1. `/boot/firmware/config.txt` で `camera_auto_detect=0` にし、`[all]` の下に `dtoverlay=imx519` を書く（公式）
2. AF を使うために Arducam 版 libcamera を入れる（公式）

   ```bash
   ./install_pivariety_pkgs.sh -p libcamera_dev
   ./install_pivariety_pkgs.sh -p libcamera_apps
   ```

3. Picamera2: Arducam のガイドは libcamera 0.0.10 以上と `sudo apt install picamera2 --upgrade` を前提にしている（公式）

- インストールスクリプトは `apt --reinstall install ./xxx.deb` で libcamera を置き換える。そのため `apt upgrade` で RPi 版に戻る可能性がある（**推定**）。対策として `apt-mark hold` などで固定することを検討する
- tuning ファイルの場所: Pi 4 は `/usr/share/libcamera/ipa/rpi/vc4/`（Pi 5 は `pisp/`）
- Buster は非対応
- 固定焦点モデルでは `vcm=off` が必要（この製品は AF モデルなので不要）
- オーバーレイの引数: `rotation`、`orientation`、`media-controller`、`cam0`、`vcm`

## RAW / DNG

- `rpicam-still -r`（`--raw`）で DNG も保存する（公式）。DNG 書き出しは `SRGGB10_CSI2P` などの 10bit Bayer に対応している
- Picamera2 では `capture_file("x.dng", name="raw")`、`request.save_dng()`、`helpers.save_dng()` が使える（公式）
- IMX519 で DNG が保存できることを明記した文書は無い（推定で可能）

## HDR

- Arducam は "supports SME-HDR" と書いているが、**libcamera / rpicam-apps からは使えない**（公式のソースで確認）
  - カーネルドライバに HDR の制御が無い
  - rpicam-apps のセンサー HDR 処理は IMX708 専用
  - tuning ファイルに `rpi.hdr` が無い
- `--hdr single-exp` は Raspberry Pi 5 以降でしか使えない
- → **露出ブラケットを撮ってソフト側で合成する**

## 取り扱いの注意

- 配線: Pi 4 では金属端子を HDMI 側に向ける（[Quick Start](https://docs.arducam.com/Raspberry-Pi-Camera/Native-camera/Quick-Start-Guide/)）
- ESD（静電気）に注意し、電源を切ってから接続する
- 高温を避ける。フレキケーブルを折り曲げない。急な温度・湿度変化を避ける（レンズが曇る）
- トラブル時（[Troubleshooting](https://docs.arducam.com/Raspberry-Pi-Camera/Native-camera/Troubleshooting/)）
  - `[all]` の下に `dtoverlay=imx519` があるか確認する
  - `dmesg` でドライバが読み込まれたか確認する
  - インストールでエラーが出たら `./install_pivariety_pkgs.sh -l` を実行する
- 型番: DigiKey に「B0371 は生産終了、B0371-1 が現行」という表示があった（未確認）

## 実機で確認した結果（2026-10-08、Raspberry Pi 5 `85pi`）

- **環境**: Raspberry Pi 5（8GB）、Raspberry Pi OS Trixie（64bit）、カーネル 6.18.50+rpt-rpi-2712。CAM/DISP 1 に接続し、`config.txt` は `camera_auto_detect=0` と `dtoverlay=imx519`（Pi 5 の既定ポートは CAM1）
- **認識**: `rpicam-hello --list-cameras` で `imx519 [4656x3496 10-bit RGGB]` と表示された。**Bayer 順は RGGB**。センサーモードは本書の表どおり（9 / 18 / 30 / 60 / 80 fps）
- **Arducam 版 libcamera**: `install_pivariety_pkgs.sh -p libcamera_dev` と `-p libcamera_apps` で、`libcamera0.7 0.7.2+rpt20260819-2` と `rpicam-apps 1.13.0-2` が入った。Raspberry Pi 版（`0.7.2+rpt20260817-1`）より新しい版なので、格下げではなく更新になる。`python3-libcamera` と `python3-picamera2` は Raspberry Pi 版のまま動く
  - Pi 5 用（`ipa/rpi/pisp/imx519.json`）にも `rpi.af` が入っていた
  - `apt upgrade` で戻らないように、`apt-mark hold` で固定した（`libcamera0.7 libcamera-ipa libcamera-dev librpicam-app1 librpicam-app-dev rpicam-apps*`）
  - そのときのインストーラ・deb・ログは、85pi の `~/archive/arducam-install-2026-10-08/` に残してある
- **AF**: `-t 3000 --autofocus-mode auto --autofocus-on-capture` で合焦した（約 14 cm 先の被写体で `LensPosition 7.2`）。`--immediate` を付けると AF が走らず、`LensPosition 1.0`（既定値）のまま撮れる
- **手動フォーカス**: `--autofocus-mode manual --lens-position 0` で `LensPosition 0.0` になった
- **DNG**: `rpicam-still -r` で 1 枚 32.7 MB の DNG が保存された（見積もり 約 33 MB と一致）
- **向き**: 取り付け方によっては画像が上下逆になる。`dtoverlay=imx519,rotation=0`（既定は 180）などで直せる
- 試し撮りの画像とメタデータは、home-linux の `~/data/super_imx519/sessions/2026-10-08_first-test/` にある

### Raspberry Pi Zero W での試行（2026-10-08、打ち切り）

- 32bit の Trixie（armhf）で起動し、USB 接続（`rpi-usb-gadget`）も Zero 側では上がったが、起動から約 2 分でユーザー空間が応答しなくなった
- 主な要因は 3 つと推定: RAM 512 MB のうち 256 MB が CMA に予約されていたこと、cloud-init・Bluetooth などの負荷、Imager を使わずに準備した SD で `userconfig.service`（初回ユーザー作成ダイアログ）が動いたこと
- 初回の cloud-init では `rpi-usb-gadget on` が 15 秒の制限時間を超えて「失敗」扱いになり、自動再起動されなかった。SSH 鍵と sudo の設定も反映されなかった
- Arducam 版 libcamera の armhf 版は ARMv6 向けにビルドされている（ELF の `Tag_CPU_arch: v6`）ので、ソフト面では Zero W でも動く見込みはある
